# Umsetzungsplan: Umbau von PHP/Apache auf Caddy

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Ziel:** Die Platzhalterseite läuft auf `caddy:2-alpine` statt auf PHP 7.3 mit Apache, ohne
Bootstrap, bei gleichem Verhalten nach aussen.

**Vorgehen:** Zuerst entsteht der Rauchtest, der das gewünschte Verhalten festhält und gegen das
heutige Image fehlschlägt. Dann wird die Laufzeit getauscht, bis er grün ist. Danach folgen
Aussehen, Entwicklungswerkzeug und Pipeline — jeder Schritt für sich prüfbar.

**Technik:** Caddy 2 (Alpine), Caddy-Templates (`env`), Docker Compose, GNU Make, Bash.

**Spec:** `docs/superpowers/specs/2026-08-15-2051-caddy-umbau-design.md`

## Rahmenbedingungen

- Alles im Quellcode ist Englisch: Bezeichner, Kommentare, Commit-Nachrichten, Skriptausgaben.
- Commits folgen Conventional Commits. Der Umbau als Ganzes ist ein `feat`, kein Breaking Change.
- Basis-Image ist genau `caddy:2-alpine`, nicht `latest`.
- Die Umgebungsvariablen heissen unverändert `APP_NAME` und `APP_TEXT_LEAD` und behalten ihre
  Vorgabewerte `amber` und `Simple Docker Placeholder Website`.
- `APP_ENV` entfällt ersatzlos; `X-Robots-Tag: noindex, nofollow` wird immer gesetzt.
- Die Site-Wurzel im Container ist `/app`.
- Der Entwicklungsport ist `127.0.0.1:8080`.
- Neue Make-Ziele tragen eine `## `-Beschreibung und stehen in `.PHONY`.

### Task 1: Rauchtest

Der Test beschreibt, was der Container können muss, und läuft gegen ein beliebiges Image. Er
entsteht zuerst und schlägt gegen das heutige PHP-Image fehl.

**Dateien:**
- Anlegen: `scripts/smoke.sh`

**Schnittstelle:**
- Liefert: `scripts/smoke.sh <image>` — startet einen Container aus `<image>`, prüft ihn und gibt
  bei einem Fehlschlag einen Exit-Code ungleich 0 zurück. Task 4 und 5 rufen genau diese Form auf.

- [ ] **Schritt 1: Rauchtest schreiben**

`scripts/smoke.sh`:

```bash
#!/usr/bin/env bash
# Smoke test for the placeholder image: starts a container from the given image
# and checks the four things that can break without anyone noticing.
set -euo pipefail

IMAGE="${1:?usage: smoke.sh <image>}"
NAME="amber-smoke-$$"

cleanup() { docker rm -f "$NAME" >/dev/null 2>&1 || true; }
trap cleanup EXIT

docker run -d --name "$NAME" -p 127.0.0.1::80 \
  -e APP_NAME=smoke-name \
  -e APP_TEXT_LEAD=smoke-lead \
  "$IMAGE" >/dev/null

PORT="$(docker port "$NAME" 80 | head -1 | cut -d: -f2)"
BASE="http://127.0.0.1:$PORT"

for _ in $(seq 50); do
  curl -sf "$BASE/" >/dev/null 2>&1 && break
  sleep 0.2
done

FAILED=0
check() {
  local label="$1" haystack="$2" needle="$3"
  if [[ "$haystack" == *"$needle"* ]]; then
    printf 'ok   %s\n' "$label"
  else
    printf 'FAIL %s\n       expected to contain: %s\n       got: %s\n' "$label" "$needle" "$haystack"
    FAILED=1
  fi
}

root="$(curl -s "$BASE/")"
check "page shows APP_NAME" "$root" "smoke-name"
check "page shows APP_TEXT_LEAD" "$root" "smoke-lead"
check "unknown path serves the page" \
  "$(curl -s -o /dev/null -w '%{http_code}' "$BASE/does/not/exist")" "200"
check "robots header is set" "$(curl -si "$BASE/")" "X-Robots-Tag: noindex, nofollow"
check "stylesheet is served as css" "$(curl -si "$BASE/style.css")" "text/css"

[[ $FAILED -eq 0 ]] && printf '\nall checks passed\n' || printf '\nsmoke test failed\n'
exit $FAILED
```

- [ ] **Schritt 2: Ausführbar machen**

```bash
chmod +x scripts/smoke.sh
```

- [ ] **Schritt 3: Gegen das heutige Image laufen lassen**

```bash
docker build --tag amber:before .
./scripts/smoke.sh amber:before
```

Erwartet: Fehlschlag. Das heutige Image liefert kein `/style.css` und setzt den Robots-Header nur
abhängig von `APP_ENV`. Damit ist belegt, dass der Test wirklich prüft und nicht nur grün leuchtet.

- [ ] **Schritt 4: Commit**

```bash
git add scripts/smoke.sh
git commit -m "test: add smoke test for the placeholder image"
```

### Task 2: Laufzeit auf Caddy umstellen

**Dateien:**
- Anlegen: `docker/caddy/Caddyfile`, `app/index.html`, `app/style.css`
- Ersetzen: `Dockerfile`
- Löschen: `main/` (gesamter Ordner), `docker/apache/000-default.conf`
- Ändern: `.gitattributes:1`

**Schnittstelle:**
- Nutzt: `scripts/smoke.sh` aus Task 1
- Liefert: ein Image mit Site-Wurzel `/app`, das `index.html` als Template rendert und
  `style.css` ausliefert. Task 3 gestaltet genau diese `app/style.css` aus.

- [ ] **Schritt 1: Caddy-Konfiguration anlegen**

`docker/caddy/Caddyfile`:

```
:80 {
	root * /app
	header X-Robots-Tag "noindex, nofollow"
	templates
	file_server
	try_files {path} /index.html
}
```

`try_files` sorgt dafür, dass jede unbekannte URL die Platzhalterseite liefert — der Ersatz für die
bisherige Apache-Rewrite-Regel. `templates` muss vor `file_server` stehen, damit die Platzhalter
ersetzt werden, bevor die Datei ausgeliefert wird.

- [ ] **Schritt 2: Seite als Template anlegen**

`app/index.html`:

```html
<!doctype html>
<html lang="de">
<head>
	<meta charset="utf-8">
	<meta name="viewport" content="width=device-width, initial-scale=1">
	<title>{{env "APP_NAME"}}</title>
	<link rel="stylesheet" href="/style.css">
</head>
<body>
<main>
	<h1>{{env "APP_NAME"}}</h1>
	<p>{{env "APP_TEXT_LEAD"}}</p>
</main>
</body>
</html>
```

- [ ] **Schritt 3: Stylesheet als Platzhalter anlegen**

`app/style.css` — vorerst nur so viel, dass die Datei existiert und ausgeliefert wird; Task 3
gestaltet sie aus:

- [ ] **Schritt 1: Compose-Datei ersetzen**

`docker-compose.yml` vollständig:

```yaml
services:
  amber:
    build:
      context: .
    ports:
      - 127.0.0.1:8080:80
    volumes:
      - ./app:/app
    environment:
      APP_NAME: amber
      APP_TEXT_LEAD: Simple Docker Placeholder Website
```

`jwilder/nginx-proxy` entfällt, ebenso der Schlüssel `version`, den aktuelle Compose-Versionen
ignorieren und anmahnen. Die Bindung an `127.0.0.1` hält den Entwicklungsport aus dem Netz.

- [ ] **Schritt 2: Makefile anlegen**

`Makefile` vollständig — die Rezeptzeilen beginnen mit einem echten Tabulator:

```makefile
.PHONY: help build up down test

help: ## Show the available targets
	@grep -E '^[a-z-]+:.*## ' $(MAKEFILE_LIST) | awk -F':.*## ' '{printf "%-8s %s\n", $$1, $$2}'

build: ## Build the image as amber:dev
	docker build --tag amber:dev .

up: ## Start the site on http://127.0.0.1:8080
	docker compose up --build --remove-orphans -d

down: ## Stop the site
	docker compose down --remove-orphans

test: build ## Run the smoke test against a freshly built image
	./scripts/smoke.sh amber:dev
```

### Task 5: Rauchtest in die Pipeline

**Dateien:**
- Ändern: `.github/workflows/release.yml` (Schritte ab `Build and push`)

**Schnittstelle:**
- Nutzt: `scripts/smoke.sh` aus Task 1

- [ ] **Schritt 1: Bauen, prüfen, dann pushen**

In `.github/workflows/release.yml` den Schritt `Build and push` durch diese drei Schritte
ersetzen; alle anderen Schritte bleiben unverändert:

```yaml
      - name: Build
        if: steps.version.outputs.new_release_published == 'true'
        uses: docker/build-push-action@v7
        with:
          context: .
          pull: true
          load: true
          tags: elnebuloso/amber:${{ steps.version.outputs.new_release_version }}

      - name: Smoke test
        if: steps.version.outputs.new_release_published == 'true'
        env:
          IMAGE: elnebuloso/amber:${{ steps.version.outputs.new_release_version }}
        run: ./scripts/smoke.sh "$IMAGE"

      - name: Push
        if: steps.version.outputs.new_release_published == 'true'
        env:
          IMAGE: elnebuloso/amber:${{ steps.version.outputs.new_release_version }}
        run: docker push "$IMAGE"
```

`load: true` legt das Image im lokalen Docker-Daemon ab, damit der Rauchtest es starten kann. Der
Push erfolgt danach von Hand statt über die Action, damit nicht zweimal gebaut wird. Der Schritt
`Login` bleibt, wo er ist, und gilt auch für diesen Push.

- [ ] **Schritt 2: Workflow prüfen**

```bash
yamllint -d "{extends: default, rules: {line-length: disable, truthy: {check-keys: false}, document-start: disable}}" .github/workflows/release.yml
```

Erwartet: keine Ausgabe.

- [ ] **Schritt 3: Reihenfolge gegenlesen**

Die Schritte müssen in dieser Reihenfolge stehen: `Checkout`, `Version`, `Set up Buildx`, `Login`,
`Build`, `Smoke test`, `Push`, `Tag and release`. Damit gilt: kein Push ohne bestandenen Test, und
kein Tag ohne erfolgten Push.

- [ ] **Schritt 4: Commit**

```bash

git commit -m "ci: smoke test the image before pushing it"
```

Der Push löst die Pipeline aus. Weil unter den Commits ein `feat` ist, entsteht ein Release: Das
Image wird gebaut, geprüft, gepusht, und erst danach entstehen Git-Tag und GitHub-Release.
Ausgehend vom letzten Tag `v1.0.0` ist das `1.1.0`. Die tatsächliche Version steht im Lauf unter
`The next release version is …` — sie ist massgeblich, nicht diese Vorhersage.
