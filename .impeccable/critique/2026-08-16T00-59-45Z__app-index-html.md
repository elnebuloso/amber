## Design-Spezifität

**Spezifisch auf schmaler Basis — nicht generisch aus Versehen.**

Die Identität hängt an drei Dingen: der geruhten Sektionsmarke, der Ton-statt-Größe-Leiter unter `h3`, und Mono als Signal über den Code hinaus. Alle drei überstehen echten Betreiber-Inhalt; eine eigens gebaute Tischlerei-Seite liest sich als gedrucktes Informationsblatt, nicht als gerenderte README.

Bemerkenswert ist, was fehlt: keine Karte, kein abgerundeter Container, kein Farbverlauf hinter dem Namen, keine „Coming Soon"-Pille, kein Icon.

Gegengewicht: die Schrift ist ein System-Stack ohne eigenen Charakter, und ein warmer Akzent auf Fast-Weiß ist der meistbegangene Pfad der Kategorie. Ohne die geruhte Marke wäre die Seite von einem Dutzend minimaler Markdown-Themes nicht zu unterscheiden — und die Marke erscheint nur, wenn der Betreiber `##` schreibt. Die Spezifität sitzt also auf der Oberfläche, für die man sich entscheiden muss. Unter den Randbedingungen (keine Abrufe, keine Build-Kette, kein Logo per Zusage) ist das der richtige Handel, nicht ein Kompromiss.

**Deterministischer Scan:** null Befunde, Exit 0, kein DEGRADED-Banner. Die Unterdrückung ist weiter tragend und berechtigt — der Detektor liest im Beleg buchstäblich den Vorlagen-Kommentar als Fließtext.

## Prioritäre Probleme

**[P1] Das Tabellenraster füllt die Spalte nicht.**
Gemessen: eine Zweispalten-Tabelle rendert ihr Raster auf 100 von 544px, eine dreispaltige auf 248. Die Linien hören mitten in der Spalte auf, während die `h2`-Linien darüber und darunter durchlaufen. `DESIGN.md` sagt an zwei Stellen das Gegenteil zu.

Ursache ist das `display: block`, das für die Scroll-Eindämmung eingeführt wurde: es macht die Tabelle zu einer Blockbox, deren innere Rasterbox `width: auto` bekommt und auf den Inhalt schrumpft. `width: 100%` bemisst den Block, nicht das Raster. `min-width: 100%` tut nichts — nachgemessen.

Warum es niemand gesehen hat: die Tabelle in `demo/index.md` füllt die Spalte zufällig genau aus. Die Prüfseite hat den Defekt maskiert.

Fix, über drei Tabellenbreiten und zwei Fensterbreiten geprüft: `th:last-child, td:last-child { width: 100% }`. Schmal und mittel füllen exakt, die breite scrollt weiter intern, Seitenüberlauf überall 0. Bekannte Decke: der ganze Rest geht an die letzte Spalte; ihn zu verteilen bräuchte `table-layout: fixed` und damit den Verzicht auf inhaltsgesteuerte Spaltenbreiten.
Befehl: `/impeccable polish`

**[P2] Die Ersatzseite zeigt den Namen des Images auf fremder Domain.**
Nachgestellt mit `APP_LANG=de` und kaputtem `{{`: `<html lang="de">` mit `<h1>amber</h1>` und `This site is not online yet.` Wer Markdown einhängt, hat keinen Grund, `APP_TEXT_LEAD` zu setzen — die README zeigt es im Markdown-Beispiel selbst nicht. `PRODUCT.md` verspricht „die Domain sagt weiter, wessen sie ist"; in diesem Zustand sagt sie, wessen das Image ist.
Fix: zwei Zeilen README statt Code — im Markdown-Abschnitt sagen, dass `APP_TEXT_LEAD` dort die Ersatzseite füllt.
Befehl: `/impeccable clarify`

**[P3] `APP_LANG` ist im Markdown-Weg nicht dokumentiert.** Wer dem Beispiel folgt, bekommt `lang="en"` über deutschem Inhalt.

**[P3] `DESIGN.md` behauptet, `--space-1` sei gelöscht.** Das Token ist zurück und wird vom Checkbox-Abstand benutzt; im Frontmatter fehlt es. Rekord-Drift, entstanden bei der Entscheidung, `DESIGN.md` für die Kleinigkeiten nicht anzufassen — ein wiederbelebtes Token ist aber genau ein Fall dafür.

**[P3] `APP_NAME=""` erzeugt leeren `<title>` und leeres `<h1>`.** Nachgestellt. Die README dokumentiert leer-gegen-ungesetzt nur für `APP_TEXT_LEAD`.

## Persona-Befunde

**Die 58-jährige Kundin, Handy, sucht die Samstagsöffnungszeiten.** Sie kommt durch. Aber `ÖFFNUNGSZEITEN` ist bei 11px, 0,14em gesperrt, in Versalien der kleinste Text auf einer Seite, die sie auf Armlänge hält — und ausgerechnet die Marke, die sie zur Orientierung braucht. Der Kontrast reicht; es geht um die Größe, und das System hat keine größere Variante ohne Bruch der eigenen Regel.

**Der Fremde fünf Sekunden nach `docker run`.** Drei verschiedene Systemzustände sehen identisch aus: Vorgabe wie ausgeliefert, leeres `APP_TEXT_LEAD`, kaputter Mount mit 500. Für den Besucher ist das die „One Surface Rule". Für den Betreiber, der unbegleitet zurechtkommen soll, ist es Mehrdeutigkeit — der 500 steht nur in den Entwicklerwerkzeugen.

**Der Maintainer im Dunkelmodus** findet nichts. Die Linienhelligkeit von 0,76 ist sichtbar richtig.

## Kleinere Beobachtungen

- Die abgehakte Checkbox trägt keinen Haken — Zustand allein über die Füllung, 4,41:1 hell. Bewusster Handel, unabhängig wieder aufgetaucht.
- `APP_NAME` wird escaped, `APP_TEXT_LEAD` führt rohes HTML aus. Gleiche Vertrauensstufe, unterschiedlich behandelt; beabsichtigt, aber nirgends erklärt.
- `--accent-ink` und `--accent-code` sind bei Textgröße nicht als Kaskade wahrnehmbar; was Link und Code trennt, sind Unterstreichung und Schriftschnitt.
- Der Lead ist der größte Text der Seite und zugleich der kontrastärmste Fließtext darauf.
- Kein Druck-Stylesheet: mit abgeschalteten Hintergründen verliert ein Codeblock seine Fläche.
- Kein Scroll-Hinweis an einem überlaufenden `pre`; jede übliche Lösung verbietet das System selbst.
- `/favicon.ico` antwortet 200 mit der Seite.

## Fragen

1. Die Prüfseite hat einen echten Defekt maskiert — die Demo-Tabelle füllt die Spalte zufällig aus. Was macht die Demo sonst noch fälschlich richtig, und gehört eine bewusst schmale Tabelle als dauerhafter Regressionsfall hinein?
2. Die Markdown-Seite hat keinen eigenen Namen; ein vergessenes `# ` lässt das einzige Versprechen des Produkts still scheitern. Ist „die Datei ersetzt die Seite vollständig" das wert?
3. `DESIGN.md` hat rund 7.000 Wörter für eine Seite mit elf Elementen — und zwei Aussagen sind unbemerkt veraltet. Ab welcher Länge hört ein Rekord auf, prüfbar zu sein?
